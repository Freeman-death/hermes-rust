# Landscape Doc Structure

Reusable reference for reading a hackathon problem-landscape markdown doc and resolving an idea request.

- **Section 1 — Summary.** Groups ideas by theme. Each theme has 4–8 ideas numbered 1–N. These numbers are what users see as "the N-th idea".
- **Section 2 — Detailed.** Same ideas, each headed `#### Idea A# — <Title>` where `A#` is the internal label. Contains: Problem, Who, Why, MVP (2 days), Sources, Hackathon fit.
- **Mapping.** User "N-th idea" → Section 1 item N → Section 2 `A#`. Always cross-check both sections before reading details; the two numberings do not coincide (e.g. 4th item in S1 is A4 in this doc, but 4th in Theme 2 would be item 12 → A12).
- **Content fields.** Every detailed idea carries: Problem / Who / Why / MVP / Sources / Hackathon fit. A short description always draws from these five fields (Problem, Who, Why, MVP, fit), never from outside sources.
